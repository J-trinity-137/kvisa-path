3. 교수님 · 심사위원 예상 질문 10초 모범 답변

Q1. 실제 학생 데이터가 없는데 어떻게 분석·검증했나요?
서울 남부·중부권 분포를 반영한 6개 가상교 432명·12주 합성 데이터를 Python으로 생성해 20개 시드에서 효과 회수율(100%)과 Null 대조군 오경보율(15%)까지 검증했고, 웹앱 1·2번 탭의 실시간 입력도 3번 탭에 즉시 합산됩니다.
Q2. 미등록 아동이나 개인정보 문제는 어떻게 처리했나요?
체류자격·비자·실명·연락처는 DB 컬럼 자체를 배제한 Zero-Tracking(Stateless) 구조입니다. 브라우저 메모리에서만 전형을 판정하고, 교육청 집계에는 10명 미만 자동 마스킹(k-익명성)과 Supabase RLS를 적용했습니다.
Q3. 기존 번역 앱(아이엠스쿨·모두의 한국어)과 뭐가 다른가요?
기존 앱은 일방 번역·초등 한국어 중심이라 중·고교 학업중단(3.4배 급증)의 핵심인 입시·비자·검정고시 함정을 못 잡습니다. 본 앱은 탐색 과정에서 병목·서류 장애·상담 이탈을 수집해 교사 개입과 교육청 정책으로 환류합니다.
Q4. 단순 정답률 대신 왜 opportunity와 응답률을 따로 보나요?
4·8주차 시험주간처럼 응답률이 급락할 때 미응답을 오답으로 처리하거나 응답자만 보면 선택 편향이 생깁니다. 배정 기회(opportunity)를 분모로 고정하고 응답률 곡선을 분리해 개입 인과성을 검증했습니다.
Q5. 왜 공통 코어(kbridge-core)와 5종 니치 앱으로 확장했나요?
21개 언어 i18n·아랍어 RTL·TTS·익명 로거를 코어로 분리해 둠으로써, 본 발표작(kvisa-path) 외에 급식(kschool-meal)·교과서(kschool-lens)·학교생존(kschool-guide)·소아과(kmed-card)까지 즉시 확장할 수 있습니다.
